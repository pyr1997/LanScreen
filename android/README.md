# LanScreen Android 电视客户端 1.3.2

原生 Java 客户端，包名 `com.lanscreen.player`，版本 `1.3.2`，`versionCode=6`，电视协议为 **3**。源码仅使用 Android 平台 API，包含普通启动器与 Android TV 启动器入口。

最低系统为 Android 6.0 / API 23，`targetSdkVersion=28` 用于旧电视侧载兼容。本包不面向 Google Play 上架，较新系统可能提示应用面向旧版 Android。实际能否安装、遥控器能否完整操作、视频能否解码，均需在目标型号和固件上验证；不保证所有 Android 电视或盒子都兼容。

## 安装与接入

1. 将 [LanScreen-TV-1.3.2.apk](../apk/LanScreen-TV-1.3.2.apk) 复制到 U 盘，使用电视允许的文件管理器安装，并按系统要求授权安装来源。已获授权的开发环境也可使用 `adb install -r`。
2. 打开“局域宣传屏”，输入服务地址、播放口令和屏幕名称。NAS 示例为 `http://<NAS_IP>:18765`，Mac 示例为 `http://<MAC_IP>:8765`；替换占位符，不附加管理网页路径。电视不能用 `127.0.0.1` 访问另一台设备。
3. 播放口令就是管理网页“连接设置”中的播放密钥，不能填管理员密码。保存后电视显示完整设备编号与接入批次。
4. 在电脑后台“电视设备 → 待审批”核对完整编号并批准。客户端约每 30 秒确认批准状态，获准后才下载和播放。
5. 在电脑网页发布清单。电视完成全部下载及 SHA-256 校验后，在当前素材结束时切换新清单；空清单持久化成功后立即撤播。

第一次接入，以及从 1.2.x 或更早版本升级，需要管理员批准。正常使用相同签名覆盖升级 1.3.0 / 1.3.1 时，原设备凭据和批准状态可保留；本次 1.3.2 修复本身不要求重复批准已有有效绑定。

## 遥控器与日常操作

| 操作 | 行为 |
|---|---|
| 确定 / 菜单 / 返回 | 打开播放控制面板 |
| 方向右键 | 切到下一项 |
| 暂停、继续 | 停止当前素材；继续时从该素材开头重播 |
| 修改连接 | 修改服务地址、播放口令和屏幕名称后重新同步 |
| 重新申请绑定 | 用户确认后创建新的设备凭据和接入批次，需管理员重新批准 |
| 退出 | 退出当前应用播放 |

播放时保持屏幕唤醒，图片按比例显示，空白区域为黑色。本版只有横屏，不含开机自启、设备所有者模式、强制锁屏、阻止退出、电视电源、音量或亮度控制。重启电视后需要手动打开应用。

## 缓存、断网与设备撤销

- 素材下载到本应用私有目录，完整校验后提交清单；未完成的文件会重新下载，不承诺按字节续传。
- 只有曾成功确认授权且未收到撤销的当前绑定，才允许使用完整缓存离线续播。待批准、已解绑或设备凭据无效时，不会因重启而恢复旧授权。
- 默认总素材缓存上限 2 GiB，至少预留 256 MiB；单播放文件上限 1 GiB。后台可调整策略。更新时需同时容纳当前受保护素材和新下载素材，空间不足会保留当前清单并报告失败。
- 完整新清单切换后回收不再使用的缓存，也支持管理员请求清理未使用缓存。清理仅针对本应用素材目录，不涉及电视其他应用、相册或系统文件。
- 离线电视无法接收新清单、解绑、播放密钥变更或清理请求。服务端删除素材不能立即擦除离线副本。解绑是撤销授权，物理缓存回收是另一项流程。
- 管理员更换共享播放密钥后，每台电视需手动更新。保存新密钥会重新同步，网络或下载失败可能中断播放，应在网络稳定时逐台操作。
- 设备凭据按服务器地址保存，缓存和授权还区分播放密钥与接入批次。地址别名或端口变化可能被视为不同连接范围，部署时应使用稳定地址。

解绑后的电视在联网收到拒绝后停止播放，并保持拒绝状态。重新使用时，在电视明确选择“重新申请绑定”，由管理员批准新的批次；普通保存、网络错误或重启不会自动解除撤销。

## 格式与性能边界

PDF / PPT / PPTX 在服务端转换为静态图片页，电视不直接运行演示文稿。动画、转场、音频和嵌入视频不会保留。需要动态效果时，先导出 MP4。推荐视频容器 MP4、视频编码 H.264、音频编码 AAC；服务端转换成功仍不能替代电视解码验收。

图片采用有界后台解码和按堆预算采样，正常切页保留上一张直到下一张准备完成。内存不足时可先释放旧图，允许短暂黑场；释放后仍不足才继续降采样保护。没有预载整份文档。平台解码器的临时缓冲及其他进程内存不包含在位图预算中，实际内存峰值、清晰度和黑场需实机观察。

视频停滞会有限重建，重复失败后跳过并退避；图片读取超时也会给出故障反馈。某些系统原生解码调用可能不响应线程中断，不能据此承诺所有卡顿都能自动恢复。

默认 HTTP 会明文传输素材和播放凭据，只用于受控局域网。客户端接受使用系统受信任证书的 HTTPS 地址，不忽略证书错误；服务端 HTTPS 代理配置需部署者另行验证，详见[部署指南](../docs/部署与使用指南.md)。

## 从源码构建

在 macOS / Linux 准备以下工具：

- JDK 17 或以上版本。
- Android SDK Platform 28。
- Android SDK Build Tools 34.0.0。
- `bash` 和 `zip`。

SDK 安装及许可接受由开发者完成。构建脚本不依赖 Gradle 或在线 Maven 仓库，但首次取得 JDK 和 Android SDK 需要自行安排。

在本目录执行：

```bash
export JAVA_HOME="/path/to/jdk17"
export ANDROID_SDK_ROOT="/path/to/android-sdk"
export BUILD_ROOT="/path/to/local-build"
export APK_OUTPUT_DIR="/path/to/new-apk-output"
bash build.sh
```

请将示例路径替换为本机位置。脚本使用 `aapt`、`javac`、`d8`、`zipalign` 和 `apksigner`。每次构建建立独立运行目录；默认输出目录是上一级 `apk/`。如果目标 APK 已存在，脚本会拒绝覆盖，应指定新的 `APK_OUTPUT_DIR`。输出包含 APK、签名与安装元数据验证结果及 SHA-256 校验文件。

未设置 `LANSCREEN_KEYSTORE` 时，脚本在本地构建目录创建或复用演示签名。这个签名只适合本地开发，不等于随附原版 APK 的签名；新生成的证书也不能恢复原 APK 的签名身份。**仓库不含原版签名私钥，重建 APK 不能保证覆盖安装随附 APK。**

需要持续维护自有分发时，创建并安全保管自己的密钥库，然后在 Bash 中设置：

```bash
export LANSCREEN_KEYSTORE="/secure/path/player-signing.jks"
export LANSCREEN_KEY_ALIAS="player"
read -r -s -p '请输入签名密码：' LANSCREEN_KEY_PASSWORD
printf '\n'
export LANSCREEN_KEY_PASSWORD
bash build.sh
unset LANSCREEN_KEY_PASSWORD
```

以上命令沿用前面设置的独立构建和输出目录。脚本假设密钥密码与密钥库密码一致。密码不写入脚本、命令行参数、`.env.example` 或仓库。自有私钥需要受控备份，并在后续版本中保持签名连续性；提交代码前检查本地构建目录和输出内容。APK 的签名校验通过仅证明包完整性和签名一致性，不证明真实电视上的播放稳定性。

## 协议说明

电视请求使用共享播放密钥、设备编号和独立设备凭据。后台管理员批准接入后，协议 3 才允许取得清单和素材。服务端保存设备凭据哈希，客户端保存本机凭据；请勿把真实请求头或凭据放入公开问题附件。

主要接口为 `POST /api/player/register`、`GET /api/player/manifest` 和 `POST /api/player/heartbeat`。清单包含发布版本、绑定批次、刷新间隔、缓存策略及媒体项；媒体项包含大小和 SHA-256。媒体 URL 必须属于同一服务器的 `/media/` 路径，客户端拒绝跨服务器媒体和 HTTP 重定向。

下载、应用和清理分别回报版本；心跳回报当前项、缓存占用、可用空间及错误。`401 key_invalid` 表示共享播放密钥无效；设备拒绝类 `403` 及协议升级要求有独立处理。离线界面的数值只是最近一次回报，不能当成即时设备状态。

## 现场验收

本轮没有执行真实电视安装和多日运行。正式使用前，至少用一台目标电视验证安装与升级、全部遥控器入口、图片/视频/PDF/PPT 混播、字体与画面比例、切页与低内存回退、清单更新、空清单撤播、解绑和重新申请、断网续播与断网重启、网络恢复、服务重启，以及覆盖实际工作时长的连续运行、温度和存储变化。
