# LanScreen 1.3.2 隐私与发布说明

本文件说明本公开源码副本的数据范围、发布内容和已知限制。它不代替部署环境自己的访问控制、数据处理制度或项目许可证。

## 1. 数据保存在哪里

| 位置 | 数据类型 |
|---|---|
| 服务端数据目录 | 上传原件、转换图片/视频、SQLite 数据库、素材名称、草稿和已发布清单、发布历史、设备名称/编号/接入批次、凭据哈希、设备回报与错误、共享播放密钥、会话密钥 |
| 浏览器 | 管理会话 Cookie，以及当前访问管理网页所需的页面数据 |
| 电视应用私有目录 | 服务地址、屏幕名称、共享播放密钥、独立设备凭据、授权状态、清单和已下载素材缓存 |
| 运行日志与备份 | 首次设置代码、故障信息，以及备份范围内的数据库、素材和密钥；可能含部署环境信息 |

Mac 默认数据目录为 `server/data`，Docker 示例挂载到容器 `/data`。管理员密码以哈希保存在数据库中；共享播放密钥、客户端设备凭据和会话签名密钥承担不同用途，不应视为同一种密码。

本版没有云端登录账号，也没有管理用户名。管理员仅通过首次设置代码创建密码，之后使用密码登录；本版没有网页密码找回。备份应按敏感资料管理，不能公开整个运行数据目录。

## 2. 网络与外部依赖

日常上传、管理、电视接入和素材同步由自己部署的服务端提供。当前业务源码未集成广告或第三方分析 SDK。首次安装 Python 依赖、构建 Docker 镜像、取得 JDK / Android SDK 及其他开发工具需要访问相应软件源，这些下载不应与日常素材服务混为一谈。

默认 HTTP 会明文传输管理密码、播放凭据和素材，适用范围是受控局域网。请勿把默认服务端口直接开放到公网。电视客户端支持系统信任证书的 HTTPS，且不会忽略证书错误；本包没有提供经过完整验收的 HTTPS 反向代理配置，需要部署者验证证书、代理转发、管理写操作和电视同步。

设备名称、素材文件名、故障内容和网络地址也可能暴露组织信息。向公开仓库提交问题前，应先检查截图、日志、HAR、请求头、数据库样例和压缩附件，使用虚构示例替换真实内容。

## 3. 授权撤销和内容清理

设备接入使用共享播放密钥与独立设备凭据，且必须经管理员批准。管理员应核对完整设备编号和接入批次，避免只凭名称批准错误设备。

以下操作有不同后果：

- **发布空清单**撤下节目，不删除服务端素材；电视需联网收到空清单并成功保存后才撤播。
- **归档素材**只改变素材库视图，原件及转换结果仍保留并占用空间。
- **彻底删除素材**删除服务端对应文件，需先移除清单引用并完成界面确认；不能立即擦除离线电视副本。
- **删除发布历史**删除历史清单及关联回报，不删除素材、不修改当前清单，也不清理电视缓存。
- **清理未使用缓存**回收电视中本应用不再使用的素材，当前清单和待切换内容受保护，需核对电视完成回报。
- **解绑**撤销设备接入，联网收到拒绝后停播；不等于物理擦除缓存。离线设备不能立即接收撤销或清理命令。

共享播放密钥轮换会阻止旧密钥的新请求，但不能远程擦除已下载副本。电视手动保存新密钥会重新同步，可能中断播放。处理敏感素材撤回时，应确认每台目标电视已联网、停播并按需要完成缓存处理。

## 4. 本公开副本的内容范围

公开副本提供 1.3.2 服务端和网页源码、Android 源码及测试、通用部署示例、中文使用说明、原版 APK 和校验资料。

不应纳入公开仓库的内容包括：

- 运行数据库、用户上传素材、电视缓存及业务备份。
- 管理密码、首次设置代码、播放密钥、设备凭据、Cookie、会话密钥、认证请求头和其他访问令牌。
- 签名私钥、密钥库、签名密码，以及包含它们的构建环境文件。
- 个人绝对路径、真实服务地址、NAS 名称、容器实例标识、生产设备记录及未经脱敏的运行证据。
- Python 虚拟环境、Android 工具链、本地构建缓存和与公开复现无关的临时文件。

版本控制忽略规则不能替代人工检查，也不会自动移除已经被跟踪或已提交到历史中的文件。发布前应同时检查当前文件和拟发布的版本历史。

## 5. APK 签名与重建

`apk/LanScreen-TV-1.3.2.apk` 是原版 1.3.2 预编译包，本轮仅复制，未重新构建或重新签名。它仍使用原 demo 签名。公开 APK 中的签名证书属于包的公开元数据，不等于签名私钥；**原私钥不随仓库公开**。

源码构建脚本在未指定自有密钥库时，会创建或复用本地演示签名。新生成的签名不保证与随附 APK 相同，无法据此重建相同签名身份，也不能保证覆盖安装已安装的原包。

需要长期维护自有分发时，应使用自己的签名并受控备份，后续升级继续保持兼容签名和正确版本号。不要把私钥、密码或密钥库提交到仓库；不要为解决签名冲突直接卸载正式设备上的应用，卸载或清应用数据会影响设备身份、设置和缓存。

具体构建方法见 [Android 客户端文档](../android/README.md)。签名校验、源码构建成功和 API 检查均不等于真实电视安装与播放验收。

运行与构建涉及 Python 及其依赖、Android 平台和构建工具、LibreOffice、FFmpeg、字体等第三方组件。项目许可证的选择不能替代这些组件自己的许可要求。打包或分发镜像、APK、字体及依赖前，应按实际包含的版本核对许可文本、署名及分发条件。

## 7. 验证与兼容边界

本公开整理没有增加开机自启，也没有新增云端账号、分组节目单或设备管控功能。PDF / PPT 转静态图片页，不保留原动画、转场、音频及嵌入视频；单文件上传上限 512 MiB，单文档最多 200 页。

Android 最低 API 23、目标 API 28 是通用侧载兼容设置，不是所有品牌、型号、固件或媒体都兼容的保证。本轮没有执行真实电视安装、播放或多日连续运行；部署者仍需在实际目标设备和素材上完成验收。源码检查、自动化测试、浏览器预览及 APK 签名验证，各自只能证明对应检查覆盖的范围。

公开部署示例采用 Linux 主机网络，默认端口 18765、内存限额 5g，具体设置在 `.env.example`。新项目名可生成新的数据卷，已有部署升级时必须核对实际原卷和项目身份，不能直接把空白新实例当成保留数据升级。完整操作见[部署与使用指南](部署与使用指南.md)。
