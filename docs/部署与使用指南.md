# LanScreen 1.3.2 部署与使用指南

本指南适用于本公开源码副本。服务端为 1.3.2，电视 APK 为 1.3.2 / versionCode 6，电视协议为 3。以下地址中的 `<NAS_IP>`、`<MAC_IP>` 均为占位符，请替换为自己的服务端局域网地址。

## 1. 部署结构与准备

```text
电脑浏览器 ── 上传、预览、编排和发布 ──→ Linux / NAS / Mac
                                               │
                                   保存素材、转换文档、提供清单
                                               │
                           局域网可达：NAS 默认 18765 / Mac 默认 8765
                                               ↓
                                    Android 电视 / 盒子
                                 申请绑定 → 批准 → 缓存播放
```

电脑不必一直打开网页，服务端需保持运行才能接收上传和提供更新。已成功确认授权、未收到撤销且拥有完整缓存的电视，可以在服务暂时不可达时继续播放原清单。

部署前准备稳定的局域网地址、足够的磁盘空间及转换资源。电视和服务端可以位于不同 VLAN，但需要现有网络策略允许连接。LanScreen 不会自动修改交换机、路由器、防火墙或 NAS 全局设置。

本版默认 HTTP 仅用于受控局域网。HTTP 会明文传输管理密码、播放凭据和素材，不应直接开放到公网。需要 HTTPS 时，参见第 8 节。

## 2. Linux / NAS 的 Docker Compose 部署

### 2.1 环境要求

- Linux Docker Engine 与 Docker Compose，或提供同等能力的 NAS。
- 能从本地 `server/Dockerfile` 构建镜像。
- 初次构建时可取得基础镜像、系统软件包和 Python 依赖。
- 部署者有权创建本项目容器和数据卷。

镜像包含 LibreOffice、中文字体、FFmpeg 和 Python 运行依赖，并以非 root 用户运行。NAS 管理界面的具体导入流程随系统版本变化；若界面不支持本地 Dockerfile 构建，可由有权限的管理员在项目目录使用 Docker Compose。

保留完整目录，不能只导入一段 YAML 而缺少 `server/`：

```text
LanScreen-v1.3.2/
  compose.yaml
  .env.example
  server/
    Dockerfile
    requirements.txt
    app.py
    render_worker.py
    conversion_runtime.py
    web/
```

### 2.2 新建独立示例实例

以下命令仅用于**新部署**。如果正在升级已有实例，先阅读第 7 节，保留原项目身份和原数据卷。

在项目根目录执行：

```bash
cp .env.example .env
```

使用文本编辑器检查 `.env` 中的示例设置：

| 变量 | 默认值 | 用途 |
|---|---|---|
| `LANSCREEN_PORT` | `18765` | 服务监听端口 |
| `LANSCREEN_MEMORY_LIMIT` | `5g` | 容器内存限额 |
| `LANSCREEN_CPU_LIMIT` | `2.0` | 容器 CPU 限额 |
| `LANSCREEN_TZ` | `Asia/Shanghai` | 容器时区 |

此 `.env` 供 Docker Compose 插值使用。Mac 启动脚本使用 `PORT` 等进程环境变量，不会自动读取这里的 Compose 设置。

示例采用 `network_mode: host`，共享 Linux 主机网络，且未指定固定容器名。项目名可以区分容器和命名卷，不能隔离监听端口。若主机已有实例或其他程序占用 18765，先为本实例选择空闲端口，再同步修改后续访问地址。若调低资源限额，应重新验证实际 PDF、PPT 和视频的转换表现。

检查配置，然后构建并启动：

```bash
docker compose -p lanscreen-demo config
docker compose -p lanscreen-demo up -d --build
docker compose -p lanscreen-demo logs --tail=100 lanscreen
```

浏览器访问：

```text
http://<NAS_IP>:18765
```

若修改了端口，访问实际端口。日志中的首次设置代码只用于当前实例初始化，按第 4 节创建管理员密码。日志可能含初始化代码和故障信息，不要直接上传到公开仓库或问题附件。

Compose 创建的命名卷挂载到容器 `/data`，保存数据库、素材、转换结果和密钥。实际卷名与 Compose 项目身份相关；不要仅靠文件夹名称猜测已有数据卷。不同项目名可能生成全新的空卷。

### 2.3 检查、停止与重启

```bash
docker compose -p lanscreen-demo ps
docker compose -p lanscreen-demo logs --tail=100 lanscreen
```

浏览器可访问 `http://<NAS_IP>:18765/api/health`。正常时响应包含版本 `1.3.2`、`ok: true`，以及 `database`、`storage`、`worker` 检查结果。健康检查不能证明电视已成功播放，也不能证明大文件转换或长时间运行正常。

停止本示例：

```bash
docker compose -p lanscreen-demo stop
```

重新启动已存在的容器：

```bash
docker compose -p lanscreen-demo start
```

停止不会删除数据。不要执行删除本项目数据卷的命令，也不要以全局清理代替本项目维护。受控关停时被中断的转换，在完成对应进程回收后保留排队状态，下次启动重新转换；普通损坏、超时等错误需要检查后手动重试。

## 3. Mac 原生试用

1. 安装 Python 3.10 或以上版本。
2. 需要 PPT / PPTX 转换时，将 LibreOffice 安装到标准应用位置。图片、视频和 PDF 不依赖 LibreOffice。
3. 完整保留项目目录，双击 `启动Mac.command`。首次在 `server/.venv` 建立独立环境并安装依赖；依赖清单未变化时，后续启动不需再次访问 Python 包仓库。
4. 打开 `http://127.0.0.1:8765`，从启动窗口读取首次设置代码，创建管理员密码。
5. 在系统网络设置查看 Mac 的局域网地址，电视填写 `http://<MAC_IP>:8765`。

启动脚本不创建系统后台服务。关闭窗口会停止服务，Mac 睡眠会影响新素材上传和更新。若本机网页可用但电视不可达，应核对服务地址、端口、局域网访问和防火墙对该服务的入站规则，不要直接关闭整个防火墙。

默认数据目录为 `server/data`，Python 环境目录为 `server/.venv`。需要指定数据位置时，可在启动脚本运行前设置 `LANSCREEN_DATA` 环境变量；迁移时应先停服务并保留原数据副本。

## 4. 首次设置与电视绑定

### 4.1 管理员初始化

管理界面只有管理员密码，**没有用户名，也没有预置通用密码**。首次进入时：

1. 从当前启动窗口或当前实例的容器日志读取首次设置代码，即接口字段 `setupCode`。
2. 在网页输入该代码，创建 10～128 个字符的管理员密码。
3. 将密码保存在自己的受控密码管理工具中。

初始化完成后代码作废，后续直接输入管理员密码。此版没有网页密码找回或邮件找回入口。忘记密码时先检查密码管理工具和授权维护记录，保留完整数据并安排受控的离线维护；不要删除数据库或数据卷来“重置”，那会影响素材、设备和发布数据。

### 4.2 安装并批准电视

1. 在允许侧载 APK 的 Android 6.0 / API 23 或以上电视、盒子安装 `apk/LanScreen-TV-1.3.2.apk`。实际安装入口依品牌及固件而异。
2. 打开“局域宣传屏”，输入服务地址、后台“连接设置”中的播放密钥和屏幕名称。服务地址使用 NAS / Mac 的局域网地址；不要使用 `127.0.0.1`。
3. 保存后，电视提交协议 3 接入申请并显示完整设备编号、接入批次。
4. 管理员在“电视设备 → 待审批”核对完整编号并批准。名称可能重复，不能只凭名称批准。
5. 电视约每 30 秒确认接入状态，批准后才下载和播放。

播放期间按遥控器确定 / 菜单 / 返回打开控制面板，方向右键切下一项。暂停后继续会从当前素材开头重播。本版没有开机自启，重启电视后应手动打开应用。

### 4.3 密钥变更与解绑

管理员密码用于后台管理；共享播放密钥用于电视接入与同步；设备还持有独立凭据。不要混用或公开这些值。

后台可设置 12～128 个字符的播放密钥，允许大小写字母、数字及 `._~-`，也可生成随机密钥。保存新密钥后，当前服务实例停止接受旧密钥发起的新请求，每台电视需手动更新。更换密钥本身不能远程擦除离线缓存；电视保存新密钥会重新同步，可能中断播放，应在网络稳定时逐台更换并检查恢复。

解绑电视后，它退出未来发布目标；联网收到拒绝后停止播放。离线设备不能立即接收撤销。解绑不等于物理删除缓存。重新使用时，由电视明确选择“重新申请绑定”，再由管理员核对并批准新批次。普通保存、网络错误或重启不会自动恢复已撤销凭据。

## 5. 上传、编排与发布

1. 登录管理网页，选择“上传素材”或将文件拖到上传区域。
2. 上传完成后继续等待处理；“上传成功”不等于“已转换成功”。失败素材不能加入清单。
3. 逐项预览。PDF / PPT 检查全部页面、中文字体、页数、比例和版式；视频检查画面与音频。
4. 加入清单，使用顺序控制调整播放次序；同一素材可重复加入。图片和文档每页可设置 1～3600 秒，视频播到结束后切换。
5. “保存草稿”仅保存编排。“发布到电视”才生成新发布版本，供所有已批准电视同步。
6. 查看下载、应用和清理阶段，再到实际电视确认播放。大文件下载和当前长视频均可能延迟新清单生效。

非空新清单在完整下载、校验并提交后，于当前素材结束时切换；空清单成功持久化后立即撤播。网页预览属于浏览器播放，可能需要点击开始才允许音视频，不含电视离线缓存，也不等于电视实机验证。

### 5.1 支持格式与容量

| 输入 | 行为 |
|---|---|
| JPG / JPEG / PNG / WebP / BMP | 转为静态图片，等比缩放，透明区域转白色，不保留动图动画 |
| MP4 / M4V / MOV / MKV / AVI / WebM | 实际解码后转为 H.264 / AAC MP4，最高 1920 × 1080 |
| PDF | 最多 200 页；加密或无法打开的文件拒绝转换；逐页生成图片 |
| PPT / PPTX | 需 LibreOffice；转为静态图片页；不支持的外链资源可能导致拒绝或转换差异 |

PDF / PPT 转换后不保留动画、转场、音频和嵌入视频。需要动态效果时，先在演示文稿软件中导出 MP4。字体缺失可能造成替换或版式变化，应使用有授权的字体并逐页预览；也可先导出检查过的 PDF。

单文件上传上限为 512 MiB，界面简称 512 MB。HTTP 请求也受同级限制，接近上限时应留出表单开销，必要时拆分。转换后单播放文件最多 1 GiB，单文档最多 200 页；清单最多 500 个素材，展开后最多 2000 个播放项。同时上传、排队和处理共用 20 个任务额度，转换串行执行。复杂文件或较低配置设备可能仍需拆分素材。

## 6. 清单、素材、历史和电视缓存

这些操作影响不同位置，不能相互替代：

| 目的 | 操作与实际影响 |
|---|---|
| 暂停所有当前节目 | 从清单移除全部内容并发布空清单；服务端素材仍保留，离线电视需联网才能收到撤播 |
| 整理素材库 | 归档；原文件仍保留，仍占服务端空间，先从草稿和已发布清单移除引用 |
| 释放服务端素材空间 | 从草稿及已发布清单移除、发布新清单，再预览彻底删除范围并输入名称确认；删除后应用内不可恢复 |
| 减少旧发布记录 | 预览后确认删除历史或保留最近若干条；当前生效记录受保护，不删除素材、不发布新清单、不清理电视缓存 |
| 释放电视中不用的素材 | 等待完整新清单切换后的自动清理，或请求“清理未使用缓存”；当前清单和待切换内容受保护 |
| 撤销某台电视接入 | 解绑；设备联网收到拒绝后停播，不保证缓存文件立即物理删除 |

电视默认素材缓存上限 2 GiB，至少预留 256 MiB，可在后台调整。更新要容纳旧清单的受保护内容和新内容。空间不足时，先检查回报和错误，再缩小清单或合理调整限额。完整空清单或无需新增下载的可复用清单可走安全交接，但仍需要能够写入状态。

服务端素材删除不能擦除离线电视副本，后台发出清理请求也不代表电视已完成。应核对电视的清理回报；对断网、已退出应用或旧客户端，不把未知状态写成成功。

发布记录的“已应用”表示电视已切换到相应清单，不代表首帧、声音或持续播放正常；“在线”只依据最近心跳，不代表电源状态。旧版本若在确认前被新版本取代，可能保留未完成状态。较早版本未保存的历史不能凭空恢复。

## 7. 备份、升级与回退

### 7.1 一致性备份

维护前安排时间，优先等待上传和转换队列空闲，然后停止本实例。Mac 备份完整 `server/data`；Docker 备份实际挂载到 `/data` 的完整卷。原数据保留，不将备份目录公开。

数据包含 SQLite 数据库、原素材、转换结果、会话密钥及设备和播放配置，不能只复制素材文件。停止后复制可降低数据库与文件不一致的风险；恢复时只允许一个实例写同一份数据。备份应验证可读取并保存在受控位置。

### 7.2 升级已有部署

本公开 Compose 是新部署示例，不能未经核对直接替换已有 NAS 的配置。新目录或 `-p lanscreen-demo` 可能产生新卷，表现为空白服务；这不代表旧数据丢失，也不是完成保留数据升级。

1. 记录已有服务版本、Compose 项目身份、实际卷、监听端口和资源设置，保留配置与完整数据备份。
2. 确认新源码与已有数据兼容，将服务端代码更新到计划使用的项目中，并继续引用实际原数据卷。
3. 保留原端口及数据映射，按实际环境调整资源；重新构建并替换本项目容器。只重启旧镜像不会加载新源码。
4. 检查健康接口版本与状态，登录核对原素材、草稿、当前清单、电视绑定和发布记录。
5. 用一台目标电视验证新发布、断网恢复和清理，再推广到其余设备。

正常使用兼容签名覆盖升级 1.3.0 / 1.3.1 客户端，可保留有效绑定；不要先卸载或清应用数据。从 1.2.x 及更早版本升级，需配套更新服务端和 APK，并逐台批准接入。

本仓库随附 APK 保留原 demo 签名，仓库不含原私钥。自行构建产生的新 demo 或自有签名，可能无法覆盖已安装的随附 APK；签名与版本兼容须在安装前核对。不要把卸载重装当成无损升级。

### 7.3 回退

保留升级前源码、镜像、配置与一致性数据备份。需要回退时，先停止新实例，再依据原配置和备份恢复，避免两个服务同时写同一数据。

Android 通常不接受直接覆盖降级到更低 `versionCode`，也不接受无关联签名覆盖安装。客户端回退需要单独确认版本、签名与设备数据保留方案；不要承诺直接安装旧 APK 就能恢复。

## 8. HTTPS 与访问控制

默认 HTTP 适用于受控局域网。需要 HTTPS 时，可在自己的环境中部署反向代理并使用电视和浏览器信任的证书，但本公开包没有提供已经完成验收的代理配置。客户端不会跳过证书校验。

启用前应验证服务地址与证书名称、完整证书链、代理转发的主机及协议头、管理网页同源校验、登录和带 CSRF 的写操作、素材下载及电视接入。仅能打开首页不能证明完整代理配置有效。避免在日志中记录认证请求头或包含密钥的请求内容。

## 9. 常见问题

| 现象 | 检查方向 |
|---|---|
| 首次设置代码无效 | 查看当前运行实例日志；已完成初始化后应直接登录，不能重复初始化 |
| 管理员密码忘记 | 此版无网页找回；检查密码管理工具，保留完整数据后安排受控离线维护，不删除数据库或卷 |
| 首次打开像空白新系统 | 核对 Compose 项目名和实际数据卷，确认是否启动了新的独立实例 |
| 端口冲突或无法启动 | 检查主机监听端口；主机网络下不同项目仍共享端口，在 `.env` 使用空闲端口 |
| 电脑能打开、电视不能连接 | 核对局域网地址、实际端口、路由与服务入站规则，电视不能填写 `127.0.0.1` |
| 电视显示待审批 | 到后台核对完整设备编号及批次并批准；检查是否连接到正确服务实例 |
| 电视提示播放口令无效 | 使用后台播放密钥，不能用管理员密码；确认是否刚换密钥或填错服务地址 |
| PPT 转换找不到 LibreOffice | Mac 检查应用安装；Docker 检查是否使用随附 Dockerfile 正确构建 |
| 中文缺字、版式变化 | 核对服务器字体和授权，逐页预览，必要时导出 PDF 后上传 |
| 转换失败 | 检查文件是否可打开、有密码、外链、超页数或超过预算；原文件完整的失败项可按提示重试，上传中断需重传 |
| 已发布但电视没更新 | 检查批准状态、下载/校验错误、电视空间，并等待当前素材结束；发布成功不等于已应用 |
| 电视空间不足 | 查看缓存与剩余空间，清理未使用缓存，缩小清单或调整限额，给新旧内容共存留空间 |
| 删除后电视仍播放旧内容 | 核对是否已发布新清单、电视是否联网并收到更新；服务端删除不会立即擦除离线副本 |
| 暂停后视频从头播放 | 本版预期行为，不保留暂停时间点 |
| 重启电视后没有自动播放 | 本版没有开机自启，需要手动打开应用 |

## 10. 目标设备验收

本轮未执行真实电视安装、播放或多日运行。正式使用前，建议先用一台目标电视完成：

1. 安装或兼容覆盖升级，核对设备编号、批准状态与全部遥控器设置入口。
2. 用有音频的视频、图片、中文 PDF 和实际 PPT 混播，核对字体、页数、画面比例、清晰度、音量与视频结尾。
3. 新清单下载与切换，发布空清单撤播，解绑及重新申请，确认界面和后台回报一致。
4. 完成首次同步后断网续播、断网重启，再恢复网络，检查清单更新和缓存清理。
5. 重启服务，核对管理员设置、素材、清单、绑定及记录保留；在获准的测试条件下验证转换中断恢复。
6. 覆盖实际工作时长和多日连续播放，观察温度、内存、磁盘与异常恢复。结果仅适用于实际测试的型号、固件和素材组合。
