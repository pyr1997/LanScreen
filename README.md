# LanScreen 局域宣传屏 1.3.2

LanScreen 是面向局域网电视和电视盒子的宣传内容播放系统。电脑浏览器负责上传素材、编排和发布，Linux / NAS 或 Mac 保存文件并转换文档，Android 客户端下载完整清单后循环播放。

本目录是 1.3.2 的公开源码整理副本，包含服务端、管理网页、Android 源码、部署示例和原版 APK。电视协议为 **3**，APK 版本为 **1.3.2 / versionCode 6**。公开整理没有增加开机自启或其他业务功能；本轮没有执行真实电视安装、播放或多日连续运行验收。

## 可以做什么

- 在中文管理网页上传图片、视频、PDF、PPT 和 PPTX，预览转换结果后编排清单。
- 设置图片和文档每页的停留时间；视频播放结束后切换下一项。
- 保存草稿，或将一份共享清单发布给所有已批准绑定的电视。
- 在后台核对电视编号并批准接入、解绑设备，查看心跳、下载、应用和缓存清理回报。
- 在电视上完整下载并校验素材后提交新清单；已获准且未收到撤销的设备可使用完整缓存断网续播。
- 查看发布记录，手动删除较早记录；归档或确认删除服务端素材，或请求电视清理未使用缓存。

一台服务提供一份共享清单。本版没有分组投放、各屏独立节目单、帧级同步、跨时段排程、竖屏、远程开关电视或强制锁屏。

## 快速开始

### Linux / NAS：Docker Compose

需要具备 Docker Engine 和 Docker Compose 的 Linux 主机，或支持本地 Dockerfile 构建的 NAS。完整保留 `server/` 及其相邻配置文件，在项目根目录执行：

```bash
cp .env.example .env
docker compose -p lanscreen-demo up -d --build
docker compose -p lanscreen-demo logs --tail=100 lanscreen
```

浏览器访问 `http://<NAS_IP>:18765`。将 `<NAS_IP>` 替换为服务端的局域网地址。首次设置代码（接口字段 `setupCode`）显示在当前实例的日志中，用它创建 **10～128 个字符**的管理员密码。管理界面没有用户名，也没有默认管理员密码；此版没有网页密码找回入口。

Compose 示例使用 Linux 主机网络。`.env` 可设置 `LANSCREEN_PORT`、`LANSCREEN_MEMORY_LIMIT`、`LANSCREEN_CPU_LIMIT` 和 `LANSCREEN_TZ`；默认值分别为 `18765`、`5g`、`2.0` 和 `Asia/Shanghai`。部署前确认端口及资源可用。不同 Compose 项目名可以隔离项目资源，但主机网络的端口仍共享；若已有服务占用 18765，应先在 `.env` 选择空闲端口。

这是一份新部署示例。**已有部署升级时必须沿用实际原数据卷及项目身份，不能把新目录、新项目名生成的空卷当成原数据卷。** 详细步骤见[部署与使用指南](docs/部署与使用指南.md)。

### Mac：原生试用

安装 Python 3.10 或以上版本。需要直接转换 PPT / PPTX 时，另行安装 LibreOffice。完整保留项目目录，双击 `启动Mac.command`，按窗口提示打开 `http://127.0.0.1:8765` 并完成首次设置。首次运行会安装 Python 依赖；关闭窗口会停止服务。

电视应填写 `http://<MAC_IP>:8765`，其中 `<MAC_IP>` 是 Mac 的局域网地址。`127.0.0.1` 仅供 Mac 本机访问。Mac 睡眠会影响素材更新。

### 电视：安装、申请和批准

1. 在允许侧载 APK 的电视或盒子安装 [LanScreen-TV-1.3.2.apk](apk/LanScreen-TV-1.3.2.apk)。
2. 打开“局域宣传屏”，输入服务地址、后台“连接设置”中的播放密钥和屏幕名称。播放密钥与管理员密码是不同凭据。
3. 电视提交申请后，在管理网页“电视设备 → 待审批”核对完整设备编号并批准。批准前不会下载和播放。
4. 上传素材 → 等待处理完成 → 逐项预览 → 加入清单 → 排序并设置秒数 → 发布到电视。
5. 查看电视的下载和应用回报，并在电视现场检查画面、声音、遥控器操作及断网恢复。

Android 最低要求为 Android 6.0 / API 23，目标 API 为 28，用于侧载兼容。不同品牌、型号、固件和系统解码器可能有差异，通用兼容目标不代表所有电视都能正常安装和播放。更多说明见 [Android 客户端文档](android/README.md)。

## 素材与播放限制

| 项目 | 本版行为 |
|---|---|
| 图片 | JPG / JPEG / PNG / WebP / BMP；等比处理，透明区域转白色，不保留动图动画 |
| 视频 | MP4 / M4V / MOV / MKV / AVI / WebM；服务端转换为 H.264 / AAC MP4，最高 1920 × 1080；最终播放取决于电视解码能力 |
| PDF / PPT / PPTX | 转换为静态图片页；PPT / PPTX 需要 LibreOffice；发布前检查中文字体、页数和版式 |
| 动态演示 | 静态页面不保留动画、转场、音频或嵌入视频；需要这些效果时，先导出 MP4 再上传 |
| 上传 | 单文件上限 512 MiB（界面简称 512 MB）；HTTP 上传请求也受同级大小限制，接近上限时需给表单开销留余量 |
| 文档和清单 | 单文档最多 200 页；清单最多 500 个素材，展开后最多 2000 个播放项；每页停留 1～3600 秒 |
| 转换与缓存 | 转换后的单播放文件最多 1 GiB；同时上传、排队及处理共用 20 个任务额度，转换串行执行；电视默认素材缓存上限 2 GiB，预留 256 MiB，可在后台调整 |
| 播放控制 | 横屏全屏；暂停后继续会从当前素材开头重播；重启电视后需要手动打开应用，本版没有开机自启 |

电视通常约每 30 秒同步。新清单完整下载和 SHA-256 校验成功后，在当前素材结束时切换；发布空清单完成持久化后立即撤播。首次同步、更新下载和接收撤播、解绑或清理命令都需要网络。

“已下载”“已应用”“已清理”是不同阶段；“已应用”不能证明每个素材已经成功播放，也不能替代真实电视的连续运行验收。在线状态依据最近心跳，不能证明电视供电状态。

## 清空、删除与清理的区别

| 操作 | 影响 |
|---|---|
| 清空并发布播放清单 | 撤下当前节目，不删除服务端素材；离线电视需要恢复连接才能收到新清单 |
| 归档素材 | 从常用素材库隐藏，原文件仍在，仍占服务端空间 |
| 彻底删除素材 | 核对文件并输入名称确认后删除服务端文件；素材必须先从草稿和已发布清单中移除 |
| 删除发布历史 | 删除历史清单快照及关联回报；当前生效记录受保护，不删除素材或电视缓存 |
| 清理未使用缓存 | 在电视收到请求后回收本应用不再使用的缓存；当前清单和待切换内容受保护 |
| 解绑电视 | 撤销设备接入；联网电视收到拒绝后停播，不等于物理擦除其缓存 |

删除服务端文件或解绑，均不能立即擦除离线电视上的副本。处理敏感内容时，需要让目标电视恢复连接并核实停播与清理状态。

## 网络与数据

默认 HTTP 会明文传输管理密码、播放凭据和素材，只适用于受控局域网。不要把默认服务端口直接暴露到公网。Android 客户端可使用受系统信任证书保护的 HTTPS 地址，且不会忽略证书错误；本项目未提供已经验收的 HTTPS 反向代理配置。启用 HTTPS 需验证证书、代理转发、管理写操作及电视访问。

素材、数据库、会话密钥与配置保存在自己管理的服务端，电视在应用私有目录保存凭据和缓存。构建镜像、首次安装依赖及下载开发工具链需要联网。备份、日志和数据库也可能含敏感信息；公开问题反馈前先脱敏。详见[隐私与发布说明](docs/隐私与发布说明.md)。
